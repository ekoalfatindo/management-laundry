Ringkasan Aplikasi

Aplikasi laundry untuk mencatat transaksi, mengelola pelanggan dan staf, mengatur katalog layanan, menerbitkan invoice A4 maupun struk thermal, menjalankan program loyalitas dan promosi, mengelola identitas perusahaan, serta memantau pendapatan. Pelanggan memiliki portal untuk melihat nota miliknya dan mengunduh PDF.

3peran: admin, karyawan, pelanggan
14permission Spatie

Yang bisa dilakukan

  • Login untuk staf dan pelanggan; staf masuk ke dashboard, pelanggan ke portal /akun.
  • Lupa kata sandi via email dengan token reset sekali pakai.
  • Dashboard KPI, grafik pendapatan 12 bulan, dan nota terbaru.
  • CRUD pengguna, karyawan, pelanggan (dengan kategori Reguler/Member), barang satuan, paket kiloan, jenis layanan.
  • Nota Paket Kiloan (berat × harga/kg) dan Barang Satuan (multi-baris + biaya layanan).
  • Status nota Diproses/Selesai/Dibatalkan dan pembayaran Belum Lunas/Lunas.
  • Diskon persen, perhitungan ulang di server, snapshot harga pada nota.
  • Program loyalitas Member dan promosi umum dengan hadiah otomatis sekali pakai.
  • Invoice A4 profesional dengan terbilang Indonesia, serta struk thermal 58/80 mm.
  • Portal pelanggan: ringkasan + daftar nota sendiri, detail invoice, dan unduh PDF A4.
  • Setup identitas perusahaan (nama + logo) yang dipakai di sidebar, login, dan invoice.
  • Pencarian, filter status/pembayaran, pagination server-side, ekspor Excel (.xlsx) rapi.
  • Dark mode, layout responsif, halaman error 403/404/419/429/500/503.

Yang sengaja tidak ada

Di luar cakupan operasional aplikasi ini:

  • Gateway pembayaran dan piutang (status Lunas hanya catatan operasional).
  • Pengeluaran operasional dan laporan laba.
  • Outlet/cabang, stok, multi-gudang.
  • Register publik, multi-tenant.
  • Toggle grid/list kosmetik dan endpoint grafik pie yang tidak dipakai.
Cara membaca dokumen ini Bagian Arsitektur menjelaskan teknologi, struktur kode, route, dan aturan bisnis. Bagian Fungsi Menu menjelaskan setiap layar beserta hak aksesnya. Bagian Deploy berisi langkah operasional untuk VPS dan shared hosting, termasuk perbedaan alur karena shared hosting umumnya tanpa SSH.

1.3 Alur request

  1. Browser meminta URL; middleware session memulihkan login.
  2. Route mencocokkan URL dan memeriksa permission:*; jika gagal menghasilkan 403.
  3. Controller memvalidasi payload lewat FormRequest (termasuk otorisasi record).
  4. Service menjalankan aturan bisnis di dalam DB::transaction bila menulis data.
  5. Controller mengembalikan Inertia::render() dengan props, atau redirect + flash sukses/gagal.
  6. Svelte merender halaman; toast SweetAlert2 membaca flash dari shared props, menunggu dialog konfirmasi tertutup, lalu hilang otomatis setelah 4,5 detik.
Error handling terpusat bootstrap/app.php merender komponen Error.svelte untuk status 403/404/419/429/500/503, baik navigasi Inertia maupun request halaman penuh. DomainException menjadi pesan flash error pada request web dan JSON 422 pada request JSON.

1.6 Aturan bisnis utama

Perhitungan kiloan

total    = round(berat × harga_per_kg)
diskon   = clamp(diskon, 0, 100)
potongan = round(total × diskon / 100)
jumlah   = total - potongan

Contoh: 3,5 kg × Rp20.000 = Rp70.000; diskon 10% → potongan Rp7.000; jumlah Rp63.000.

Perhitungan barang satuan

per baris = round(harga × jumlah_barang)
subtotal  = Σ total baris
total     = subtotal + biaya_layanan
potongan  = round(total × diskon / 100)
jumlah    = total - potongan

Biaya layanan berasal dari jenis layanan yang dipilih dan disimpan sebagai snapshot pada nota.

Potongan hadiah (loyalitas/promosi)

persen  = round(total × min(100, nilai) / 100)
nominal = min(total, nilai)
gratis  = nilai > 0 ? min(total, nilai) : total
jumlah  = max(0, total_harga - potongan)

Saat hadiah dipakai, diskon manual dipaksa 0 dan hanya satu hadiah boleh dipakai per nota. diskon_nominal menyimpan potongan sebenarnya; hadiah ditandai Digunakan dengan nota_id dan nilai_terpakai.

  • Server adalah sumber kebenaran. Pratinjau total di form hanya bantuan UI; server menghitung ulang saat menyimpan.
  • Snapshot harga. notas.harga_per_kg, notas.biaya_layanan, dan nota_barangs.barang/harga menyimpan nilai saat transaksi.
  • Hapus master tidak menghapus riwayat. Foreign key master memakai nullOnDelete; nota tetap menampilkan snapshot.
  • Nomor nota. Format # + 3 huruf kapital + 3 karakter alfanumerik, unik, dengan retry maksimal 20 kali.
  • Transaksi database. Pembuatan/pembaruan nota, perubahan status, dan pemakaian hadiah dibungkus dalam satu transaksi.
  • Diskon. Dibatasi 0–100 di server meskipun input form juga dibatasi; dipaksa 0 bila memakai hadiah.
  • Edit nota. Melepas hadiah lama, menghitung ulang nominal dari master saat ini, mengganti baris satuan, lalu menerapkan kembali hadiah pilihan.
  • Status nota. Diproses → Selesai atau Dibatalkan. Hanya Selesai yang dihitung untuk loyalitas/promosi. Nota batal tidak dapat diselesaikan.
  • Hadiah sekali pakai. Hadiah harus milik pelanggan pada nota dan berstatus Tersedia; setelah dipakai tidak dapat dipakai lagi. Pembatalan nota melepas hadiah, tetapi ditolak bila hadiah dari transaksi sumber sudah dikonsumsi nota lain.
  • Penerbitan hadiah. Loyalitas: target transaksi Selesai untuk pelanggan Member. Promosi: target transaksi dalam periode untuk kategori sasaran. reward_key deterministik menjamin satu hadiah per siklus.
  • Kedaluwarsa. Hadiah loyalitas memiliki masa berlaku hari; hadiah promosi mengikuti periode penerbitan (tanpa tanggal kedaluwarsa terpisah). Hadiah kedaluwarsa tidak dapat dipilih.
  • Terbilang. Total akhir dikonversi otomatis ke kata Bahasa Indonesia dengan akhiran “rupiah” (contoh: Rp125.000 → “Seratus dua puluh lima ribu rupiah”). Nilai resmi dihitung di server melalui App\Support\Terbilang; form memakai implementasi TypeScript yang sama untuk pratinjau.
  • Identitas perusahaan. Satu baris tabel pengaturan menyimpan nama dan path logo; nilai ini dibagikan ke seluruh halaman melalui Inertia dan dipakai pada sidebar, halaman login, serta kop invoice.
  • Format cetak. Pengguna memilih A4 atau thermal 58/80 mm sebelum mencetak; media cetak menyembunyikan navigasi, tombol, dan modal.
  • Pagination. Semua daftar memakai pagination server-side dengan pilihan 10/25/50/100 baris.

1.8 Keamanan

  • Session auth + CSRF Inertia; password di-hash bcrypt; login dibatasi 5 percobaan per email+IP.
  • Reset password memakai token acak Laravel pada password_reset_tokens, kedaluwarsa dan sekali pakai; permintaan tautan dibatasi 6/menit dan selalu memberi pesan generik agar email tidak dapat ditebak.
  • Seluruh input divalidasi FormRequest; harga tidak pernah dipercaya dari klien.
  • Logo perusahaan divalidasi sebagai gambar PNG/JPG/JPEG/WEBP maksimal 2 MB; file lama dihapus saat diganti; akses ubah dibatasi permission pengaturan.manage.
  • Mass assignment dibatasi atribut #[Fillable]; data pengguna di-escape oleh Svelte.
  • Ekspor Excel menulis seluruh teks sebagai inlineStr, sehingga nilai seperti =, +, -, atau @ tidak dieksekusi sebagai formula.
  • Portal pelanggan memfilter nota/PDF dengan pelanggan_id akun login; membuka data pelanggan lain menghasilkan 404 dan staf dialihkan dari /akun.
  • Kredensial demo hanya untuk lokal; .env tidak boleh ikut ter-upload ke repositori publik.

Nota Transaksi

GET /nota AdminKaryawan

Riwayat seluruh nota kiloan dan barang satuan dengan pencarian, filter, pagination, dan ekspor.

Filter

  • Pencarian teks pada nomor nota atau nama pelanggan.
  • Filter jenis: semua, Barang Satuan, atau Paket Kiloan.
  • Filter status: semua, Diproses, Selesai, atau Dibatalkan.
  • Filter pembayaran: semua, Belum Lunas, atau Lunas.
  • Rentang tanggal dari dan sampai (tanggal kosong = tanpa batas).
  • Jumlah baris per halaman: 10, 25, 50, atau 100.
  • Tombol Terapkan dan Reset.

Aksi

  • Lihat (ikon mata) → detail nota.
  • Ubah (ikon pensil) hanya jika punya nota.update.
  • Hapus (ikon tempat sampah) hanya admin (nota.delete), dengan dialog konfirmasi.
  • Ekspor Excel mengikuti filter aktif.
  • Buat Nota jika punya nota.create.

Ekspor Excel

Nama berkas laporan-nota-YYYYMMDD-HHMMSS.xlsx. Sheet Laporan Nota memuat judul perusahaan, waktu cetak, jumlah nota, dan ringkasan filter aktif; header dibekukan, auto-filter aktif, dan baris TOTAL menjumlahkan berat, total harga, serta jumlah. Urutan baris kronologis. Kolom:

No Nota, Jenis, Nama Pelanggan, Layanan, Waktu, Berat (kg), Harga per kg, Biaya Layanan, Total Harga, Diskon (%), Jumlah, Status, Pembayaran.

Angka memakai format Rupiah "Rp" #,##0, tanggal dd/mm/yyyy hh:mm, dan pengaturan cetak lanskap A4 fit-to-width. Teks ditulis sebagai inlineStr sehingga tidak dieksekusi sebagai formula.

Pada tabel aplikasi, setiap baris juga menampilkan badge jenis nota (teal), status nota, status pembayaran, dan label hadiah bila ada.

Edit dan Hapus Nota

GET/PUT/DELETE /nota/{id} AdminKaryawan

Edit

  • Form sama dengan pembuatan; jenis nota tetap dan tidak dapat diganti.
  • Hadiah lama dilepas lebih dulu, nominal dihitung ulang dari master saat ini, lalu hadiah yang dipilih diterapkan kembali.
  • Hadiah terpasang tampil pada select dan dapat dilepas lewat Tanpa hadiah atau diganti tanpa mengganti pelanggan; melepas hadiah mengaktifkan kembali diskon persen.
  • Nota berstatus Dibatalkan bersifat final: halaman edit ditolak dan tombol Ubah disembunyikan.
  • Untuk nota satuan, seluruh baris lama diganti dengan baris pada form.
  • Setelah simpan, kembali ke detail dengan toast sukses.

Hapus

  • Hanya admin. Karyawan tidak melihat tombol dan endpoint DELETE menghasilkan 403.
  • Nota yang hadiah sumbernya sudah dipakai nota lain tidak dapat dibatalkan/dihapus; hadiah yang belum terpakai dilepas.
  • Dialog konfirmasi menjelaskan bahwa baris barang pada nota ikut dihapus.
  • Header dihapus, baris nota_barangs terhapus melalui cascade.

Loyalitas Member

GET/PUT /loyalitas Admin

Konfigurasi program loyalitas untuk pelanggan kategori Member. Hadiah terbit otomatis setiap kali jumlah transaksi Selesai mencapai target.

  • Field program: nama, deskripsi, target transaksi, tipe hadiah (persen/nominal/gratis), nilai hadiah, masa berlaku (hari), dan status aktif. Untuk Gratis Cuci, nilai 0 berarti gratis penuh; nilai > 0 menjadi batas maksimal potongan. Tipe persen dibatasi 1–100, dan nilai menyesuaikan otomatis saat tipe hadiah diganti.
  • Penerbitan: siklus = intdiv(jumlah Selesai, target); satu hadiah per siklus dengan kunci deterministik LOY-{program}-{user}-{siklus}.
  • Riwayat: hadiah Tersedia, Digunakan, Kedaluwarsa, dan Dibatalkan beserta tanggal peroleh/pakai.
  • Perubahan konfigurasi: menyimpan program menyinkronkan seluruh pelanggan; target turun mencabut hadiah tersedia berlebih, target naik menerbitkan siklus baru.
  • Akses: hanya admin dengan loyalitas.manage; karyawan mendapat 403.

Promosi

GET/POST/PUT/DELETE /promosi Admin

Promosi umum yang dapat menyasar pelanggan Reguler, Member, atau semua kategori, dengan periode dan syarat tertentu.

  • Field: nama, deskripsi, syarat, target kategori, target transaksi, tipe/nilai hadiah, tanggal mulai–selesai, dan status aktif. Untuk Gratis Cuci, nilai 0 berarti gratis penuh; nilai > 0 menjadi batas maksimal potongan. Tipe persen dibatasi 1–100, dan nilai menyesuaikan otomatis saat tipe hadiah diganti.
  • Penerbitan: hanya bila promosi aktif, pelanggan memenuhi kategori, dan transaksi Selesai berada dalam periode; kunci PRM-{promo}-{user}-{siklus}.
  • Tidak aktif/kedaluwarsa: tidak menerbitkan hadiah baru; hadiah lama tetap dapat dipakai sampai habis.
  • Ledger terpisah: promosi dan loyalitas memiliki sumber/kunci berbeda, sehingga satu transaksi dapat dihitung untuk keduanya, tetapi hanya satu hadiah yang boleh dipakai per nota.
  • Akses: hanya admin dengan promosi.manage; karyawan mendapat 403.

  • Toast: notifikasi sukses/gagal tampil di kanan atas dengan progress bar dan tombol tutup; menunggu dialog konfirmasi tertutup dan hilang otomatis setelah 4,5 detik.
  • Konfirmasi hapus: dialog SweetAlert2 dengan judul aksi, pesan kontekstual, tombol Ya, hapus (rose) dan Batal (fokus awal), bertema oranye/rose termasuk mode gelap.

Teks footer tidak ditulis langsung di template: semuanya dibaca dari konstanta FOOTER di lib/footer.ts yang disimpan XOR + base64, didekode saat dimuat, dan dibekukan dengan Object.freeze.

  • Sidebar: gradien oranye hangat (light/dark) dengan tombol hamburger untuk merampingkan menu menjadi rail ikon di desktop; pilihan tersimpan di localStorage.
  • Responsif: sidebar menjadi drawer pada layar kecil; tabel dapat digeser horizontal.
  • Latar konsisten: halaman login memakai gradasi hangat (radial + linear) yang selaras dengan sidebar, panel brand oranye gelap, input dengan fokus oranye, dan tombol gradient oranye—baik mode terang maupun gelap.

  • Format cetak: detail nota menyediakan pilihan A4, thermal 80 mm, dan thermal 58 mm; pratinjau mengikuti format yang dipilih.

3.2 Checklist sebelum deploy

  • APP_ENV=production dan APP_DEBUG=false.
  • APP_KEY terisi dan tidak berubah setelah data dibuat.
  • APP_URL memakai URL HTTPS final (tanpa garis miring di akhir).
  • APP_TIMEZONE=Asia/Jakarta dan APP_LOCALE=id.
  • Kredensial database produksi sudah dibuat; bukan akun root.
  • public/build/manifest.json ada (hasil npm run build).
  • File public/hot dihapus — file ini hanya untuk mode pengembangan.
  • Folder storage dan bootstrap/cache dapat ditulis.
  • php artisan storage:link sudah dijalankan (logo Setup tampil).
  • SMTP terisi bila fitur lupa password dipakai; uji satu email reset.
  • Kredensial demo diganti atau data demo tidak dipakai.
  • HTTPS aktif dan cookie sesi berfungsi.
Jangan pernah deploy public/hot Saat npm run dev berjalan, Laravel membuat public/hot berisi alamat Vite lokal (mis. http://127.0.0.1:5173). Shared hosting seperti Hostinger hPanel umumnya tidak menyediakan SSH/Composer/Artisan. Karena itu, dependensi dan aset dibangun di komputer lokal, database disiapkan sebagai file SQL, lalu diunggah.     Di hPanel, buka pengaturan domain/subdomain dan ubah document root menjadi /home/uXXXXX/laundry/public bila tersedia. Ini cara paling aman karena .env, vendor, dan kode lain berada di luar web root.

    ->handleRequest(Request::capture());
    Salin juga public/.htaccess ke public_html. Jangan letakkan .env di dalam public_html.

    Buka phpMyAdmin dari hPanel, pilih database, lalu tab Import dan unggah laundry_prod.sql. Pastikan charset utf8mb4. Jika impor terpotong karena batas unggah, minta penyedia menaikkan batas atau impor per bagian.

  7. Buat file .env

    Salin .env.example menjadi .env melalui File Manager, lalu isi nilai produksi (sama seperti tabel environment di atas) dengan kredensial database dari hPanel dan APP_KEY hasil langkah 1. Pastikan APP_URL=https://domainanda.com dan APP_DEBUG=false.

  8. Atur izin folder

    Melalui File Manager, set permission storage dan bootstrap/cache (beserta isinya) menjadi 775. Jika hosting memakai pemilik file yang sama dengan proses PHP, 755 biasanya cukup untuk file dan folder; yang penting proses PHP dapat menulis cache, session, dan log.

  9. Buat symlink storage tanpa SSH

    Logo perusahaan disimpan di storage/app/public/logos dan harus dapat diakses lewat public/storage. Karena hPanel tidak menyediakan terminal, unggah berkas sementara public/buat-storage-link.php berikut melalui File Manager: 

    <?php
$target = dirname(__DIR__).'/storage/app/public';
$link = __DIR__.'/storage';

if (is_link($link)) {
    echo 'Symlink sudah ada: '.readlink($link);
    exit;
}

if (!is_dir($target)) {
    mkdir($target, 0775, true);
}

echo symlink($target, $link) ? 'Symlink berhasil dibuat.' : 'Gagal membuat symlink.';

    Buka https://domainanda.com/buat-storage-link.php sekali, pastikan tertulis “Symlink berhasil dibuat.”, lalu hapus berkas tersebut. Jika hosting memblokir fungsi symlink(), minta penyedia mengaktifkannya atau arahkan dukungan untuk membuat symlink manual dari public/storage ke storage/app/public.

  10. Aktifkan HTTPS dan uji

    Aktifkan SSL gratis di hPanel dan paksa HTTPS. Buka https://domainanda.com/up, lalu login. Uji setiap menu, pembuatan nota, cetak struk, dan ekspor Excel.

  11. Amankan akun demo

    Jika memakai database hasil seeder demo, segera ganti password seluruh akun staf, hapus akun/nota demo yang tidak diperlukan, dan jangan biarkan kredensial password aktif di produksi.

Jangan unggah cache config lokal File di bootstrap/cache/*.php dapat berisi path absolut komputer pengembang. Hapus file cache tersebut sebelum ZIP, atau jangan sertakan folder bootstrap/cache.
